# 页面结构化提示词生成规范 (Page to Prompt Generate)

当用户触发此技能，要求为某个特定页面（如："请为我生成申请单审核详情页的提示词"）生成 AI UI 提示词时，你的任务是联合读取《UI页面清单》与底层的《逻辑资产说明书》，通过"填空拼装"的方式，输出一份包含 5 大结构块的 Structural Prompt。

---

## 1. 前置准备与输入定位（执行前必读）

在执行任何拼装逻辑之前，必须先完成以下资产文件定位与完整性检查。

### 1.1 《UI页面清单》定位

按以下优先级顺序确定输入文件：

1. **用户明确指定文件**：若用户在指令中明确了文件名（如 `注册申请单_UI页面清单.md`），直接读取该文件，无需额外确认。
2. **用户未指定文件**：扫描 `docs/page-list/` 目录，列出所有匹配 `*_UI页面清单.md` 的文件，并向用户询问：
   > 「发现以下 UI 页面清单，请问您希望从哪个模块中选择页面生成提示词？」

   等待用户确认后再继续执行。
3. **目录不存在或无匹配文件**：立即停止并告知用户：
   > 「⚠️ 未找到任何 UI 页面清单，请先执行 `page-list-generate` 技能生成页面清单。」

### 1.2 《逻辑资产说明书》定位

1. 根据用户选定页面所属的**模块名称**，在 `docs/logic-asset/` 目录下查找**同名**的逻辑资产说明书文件（命名规则：`[模块名称]_逻辑资产说明书.md`）。
2. **找到对应文件**：直接读取，无需询问用户。
3. **未找到对应文件**：立即停止并告知用户：
   > 「⚠️ 未找到模块【X】对应的逻辑资产说明书，请先执行 `logic-asset-generate` 技能为该模块生成说明书。」

### 1.3 章节缺失容错规则

在提取逻辑资产内容的过程中，若被引用的章节（如【1.1 核心实体】、【2.1 状态流转决策表】、【2.2 核心字段校验规则】）**在文档中不存在或内容为空**时：

- **严禁停止执行，严禁自行推断或凭空编造业务属性。**
- 必须在生成的提示词中，对应缺失章节的位置，插入如下占位标注：

  ```
  【⚠️ 待补充：原逻辑资产说明书中该章节缺失，以下内容请人工核对后补全】
  ```

- **文档结构完全异常**：若整个文件完全找不到任何状态机、实体或决策表内容，停止执行并告知用户：
  > 「⚠️ 文档结构异常，请确认该文件是否由 `logic-asset-generate` 技能生成。」

## 2. 上下文提取清单（基于第 1 节已加载的资产）

> **无需重新读取文件**，仅从第 1 节已定位并加载的内容中，提取以下信息，备用于第 3 节拼装。

- **从《UI页面清单》提取**：
  - 当前目标页面的【端/角色】
  - 【页面类型】（如：列表页、详情页、表单页）
  - 【关联业务操作及核心按钮】列表

- **从《逻辑资产说明书》提取**：
  - 【1.1 核心实体（主表）】：主实体全量字段列表（含字段名、说明）
  - 【1.1 子实体】：若主实体章节下存在子实体描述（通常标注为"子实体：XXX"，如 InquiryItem、TechnicalClause、ProductionClause 等），**必须一并提取其全量字段**，并记录：
    - 子实体名称与说明
    - 与主实体的关联关系（1:1 / 1:N）
    - 各子实体的全量字段列表（含字段名、说明）
  - 【1.2 核心枚举与数据字典】：各枚举字段的选项值列表（主表与子实体均适用）
  - 【2.1 状态流转决策表】：操作角色、流转动作、前置阻断条件
  - 【2.2 核心字段校验规则】：字段校验时机、规则说明、错误提示文案（主表与子实体均适用）

> 提取时如遇章节缺失，严格按照第 1.3 节的容错规则处理。

---

## 3. 核心拼装算法（5 大结构块）

你输出的提示词必须严格按照以下 5 个结构块（以纯文本代码块形式输出，方便用户一键复制）进行组织：

### 3.1 页面定位与结构 (Page Skeleton)
- 提取《UI页面清单》中的【端/角色】、【页面名称】和【页面类型】。
- **端侧独立布局规范（重点）**：必须根据【端/角色】标识判断目标平台，并给予 AI 截然不同的布局设定：
  - **若为 APP端（移动端）**：强制采用纵向流式布局。列表页应使用卡片式流式列表（配合下拉刷新/无限滚动）；详情页和表单页应使用顶部 NavBar（带返回键）及底部固定操作栏（Bottom Action Bar）或悬浮按钮（FAB）。坚决禁止使用宽版表格和横向面包屑。
  - **若为 WEB端（PC端）**：采用大屏宽版布局。列表页应使用带顶置复杂筛选器的数据表格（Data Table）和底部分页；详情页应包含分步器/状态条和分区块的卡片展陈。

### 3.2 数据展示层 (Data Layer)
- 提取《逻辑资产说明书》的【1.1 核心实体（主表）】字段列表。
- 将需要在该页面中展示/录入的字段罗列出来，并标注是否必填（参考【2.2 核心字段校验规则】判断）。
- **权限字段过滤（重要）**：提取字段前，必须先结合【4. 权限与数据隔离矩阵】，按照当前页面的角色过滤掉不可见字段。只有该角色有权限查看/编辑的字段才能出现在提示词中。
- **约束**：若为只读详情页，明确告知 AI "设置为只读文本展示"；若为表单页，明确告知 AI 使用输入框/下拉框（若是下拉框，从【1.2 核心枚举与数据字典】中带出选项值）。
- **主从结构渲染约束（重要）**：若第 2 节提取阶段已识别到存在子实体，必须在提示词中明确描述主从布局，规则如下：
  - **1:N 子实体**（如 InquiryItem 询单明细）：在提示词中明确要求使用「主表基础信息区 + 明细列表区」上下分区布局，明细列表须支持动态新增/删除行。对于 APP端，使用卡片式列表追加；对于 WEB端，使用可编辑内嵌数据表格（Inline Editable Table）。
  - **1:1 子实体**（如 TechnicalClause 技术条款、ProductionClause 生产条款）：在提示词中明确要求，该子实体的字段在对应明细行的「展开面板（Expandable Row / Collapse Panel）」内录入，而非独占一个新页面。
  - 每个子实体的字段必须在提示词中单独分区列出，并在字段 label 前用方括号标注所属实体（如：`[明细] 期望交货日期*`、`[技术条款] 制造工艺*`），防止 AI 混淆主表与子表字段。

### 3.3 交互操作层 (Action Layer)
- 提取《UI页面清单》中该页面对应的【关联业务操作及核心按钮】。
- 为每个按钮指定类型（如：主操作为 Primary，危险操作为 Danger）。
- 明确指出哪些操作会触发模态框（Modal）或对话框。

### 3.4 细节流转与校验逻辑 (Logic & Validation)
- 提取《逻辑资产说明书》的【2.1 状态流转决策表】和【2.2 核心字段校验规则】。
- 明确写出：必填项要求（红星）、表单报错 Toast 提示文案，以及点击按钮后的跳转或反馈动效。

### 3.5 状态条件渲染 (Conditional Rendering)
- **数据源**：读取《逻辑资产说明书》的【2.1 状态流转决策表】，提取每个操作按钮（或操作入口）所对应的**前置状态条件**（即：该按钮在何种记录状态下才应出现）。
- **生成规则**：为每个需要条件渲染的按钮，在提示词中明确写出以下格式的约束：
  > `仅当记录状态为【X】时，才渲染/显示【按钮Y】；其余状态下该按钮不可见（或置灰禁用）。`
- **隐藏 vs 禁用 区分规则（重要）**：对于每个按钮，必须在提示词中明确写明该按钮在非法状态下的处理方式，必须二选一：
  - **「不渲染 / 隐藏」**：若该操作对当前角色完全不应该知道（如属于其他角色的操作入口），则直接不渲染该按钮，页面中不出现任何痕迹。
  - **「渲染但置灰禁用」**：若该操作对当前用户可见、但当前状态或条件暂不满足（如表单校验未通过、状态不符合），则渲染该按钮但设置为 `disabled` 灰化状态，鼠标 hover 时显示 Tooltip 说明禁用原因。
- **约束**：
  - 若某按钮无前置状态约束（始终可见），无需列入本节，直接在 3.3 节描述即可。
  - 若【2.1 状态流转决策表】章节缺失，按 1.3 节容错规则插入占位标注，严禁自行推断显隐逻辑。

## 4. 输出规范与落盘

你必须使用 `write_to_file` 工具，将拼装好的 5 大结构块内容保存为一个独立的 Markdown 文件，存放在当前项目的 `docs/ui-prompts/` 目录下。
- **命名规范**：`docs/ui-prompts/[模块名称]_[端/终端类型]_[页面名称]_UI提示词.md`
  - 示例：`docs/ui-prompts/询单_APP端_询单录入页_UI提示词.md`、`docs/ui-prompts/询单_WEB端_询单录入页_UI提示词.md`
  - **必须在文件名中包含终端类型**（APP端 / WEB端 / WEB管理端），确保同一模块下同名页面的 APP端 与 WEB端 提示词文件不会互相覆盖。

文件内部的内容应严格按照以下模板结构编写：

```markdown
# [页面名称] UI 结构化提示词

> **使用说明**：请复制以下全部内容，发送给您常用的 AI UI 生成工具。

---

### 【页面结构】
- **页面名称**：[页面名称]
- **终端类型**：[APP 移动端 / WEB PC端]
- **布局要求**：[严格根据终端类型描述布局。若是 APP端，明确要求生成 NavBar + 纵向流式卡片 + 底部固定操作栏；若是 WEB端，要求生成 数据表格/多栏卡片分布]

### 【数据与表单区】
该页面需要包含以下字段（标 `*` 为必填，需在字段 label 前显示红色星号）：
- [字段1]*：[只读/输入框/下拉框]，必填，[校验规则/字典选项说明]
- [字段2]：[只读/输入框/下拉框]，选填，[说明]

### 【功能操作区】
请在页面 [位置] 放置以下按钮：
1. **[按钮A]**：[主色/次级/危险色]，[点击后触发的交互动作]
2. **[按钮B]**：[主色/次级/危险色]，[点击后触发的交互动作]

### 【交互与校验逻辑】
- [字段级别校验要求与错误Toast提示，注意标注必填红星]
- [弹窗级别的逻辑，弹窗内的特定要求说明]

### 【状态条件渲染】
以下按钮/操作入口存在状态约束，请严格按条件控制其可见性：
- 仅当记录状态为【状态A】时，显示【按钮X】；其余状态下不可见。
- 仅当记录状态为【状态B】时，显示【按钮Y】；其余状态下置灰禁用。
```

文件落盘后，在对话中向用户提供该生成文件的本地链接，提示用户可直接复制该文件内容。

---

## 5. 执行约束
- **拒绝凭空想象**：提示词中的字段、校验规则、按钮名称，必须 100% 来源于逻辑资产说明书，严禁你自己创造业务属性。
- **化繁为简**：用户每次只能请求**一个特定页面**的提示词。若用户未指定页面，请先让他从《UI页面清单》中选择一个。
- **落盘后必须回链**：文件写入成功后，必须在对话中以 Markdown 链接形式返回文件的本地路径，供用户一键打开。严禁只告知"已生成"而不附链接。
