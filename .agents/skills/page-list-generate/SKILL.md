# UI 页面清单生成规范 (Page List Generate)

当用户触发此技能时，你的任务是基于指定的《逻辑资产说明书》，通过严格的逻辑推导算法，自动化地提取出前端 UI 页面清单及关联业务操作。

---

## 1. 前置准备与输入定位（执行前必读）

在执行任何推导算法之前，必须先完成以下输入定位检查：

### 1.1 输入文件定位

按以下优先级顺序确定输入文件：

1. **用户明确指定文件**：若用户在指令中明确了文件名（如 `注册申请单_逻辑资产说明书.md`），直接读取该文件，无需额外确认。
2. **用户未指定文件**：扫描 `docs/logic-asset/` 目录，列出所有匹配 `*_逻辑资产说明书.md` 的文件，并向用户询问：
   > 「发现以下逻辑资产说明书，请问您希望为哪个（些）生成 UI 页面清单？」
   等待用户确认后再继续执行。
3. **目录不存在或文件为空**：立即停止并告知用户：
   > 「⚠️ 未找到任何逻辑资产说明书，请先执行 `logic-asset-generate` 技能生成说明书。」

### 1.2 章节缺失容错

在推导过程中，若文档中缺少某个被引用的章节（如无第9章），**不得停止执行**，须在推导结果的对应行备注：
> `⚠️ 原文档缺少该章节，已基于现有信息推导，结果仅供参考`

- **文档结构完全不符**：若文件存在但完全找不到任何状态机或决策表内容，停止执行并告知用户：
  > 「⚠️ 文档结构异常，请确认该文件是否由 `logic-asset-generate` 技能生成。」

---

## 2. 核心推导算法（AI 内部思维链）

在生成清单前，请在后台严格执行以下 3 步矩阵降维分析：

### 2.1 提取角色（划定视图端边界）
- **数据源**：读取逻辑资产说明书的 `第2.1节（状态流转决策表）` 的【操作角色】列，以及 `第4章（权限与数据隔离矩阵）`。
- **推导逻辑**：识别出所有涉及的人类角色（如客户、管理员、业务员）。凡是带有独立角色的，必须为其分配独立的前端"端"或"工作台视图"。绝对禁止跨角色混合页面操作。

### 2.2 过滤停顿节点（确定必须的页面）
- **数据源**：读取 `第1.3节（生命周期状态机）` 及 `第2.1节（决策表）`。
- **推导逻辑**：扫描状态机，找出所有**需要人工干预（操作角色非"系统"）**的状态节点。
  - 对于触发条件为用户点击操作的状态，必须要有对应的 UI 页面（表单、详情或弹窗）。
  - 对于流转角色为"系统"的静默后台任务（如：系统调用API超时重试），直接剔除，不需要为其绘制前端页面。

### 2.3 组装页面与流转按钮（提取业务操作）
- **数据源**：读取 `第2.1节（决策表）` 与 `第9章（用户交互说明）`。
- **推导规则**：
  - **列表页标配**：每个角色默认必须分配一个【列表页/台账】，用于数据查询与筛选。
  - **列表页筛选维度**：结合该实体的生命周期状态枚举值生成【状态】筛选下拉，并根据第4章（权限矩阵）确定该角色可见的数据范围，在表格的【关联业务操作】列中以"筛选：状态/时间范围/关键字"格式标注。
  - **表单与详情页**：基于角色的操作权限，为特定状态分配对应的【表单页】（用于初始录入或补充数据）或【详情页】（用于审核、查看只读数据）。
  - **关联业务操作提取**：该页面下允许执行的决策表【流转动作】，即为该页面的核心功能按钮。若动作的前置阻断条件要求录入额外信息（如审核驳回需填原因），需标记此操作为【弹窗操作 (Modal)】。

## 3. 输出规范与模板

基于上述推导，向用户输出完整的 UI 页面清单。
必须使用 Markdown 表格进行输出，表格表头严格遵循以下格式：

```markdown
### [模块/实体名称] UI 页面清单

| 端/角色 | 页面名称 | 页面类型(列表/详情/表单/弹窗) | 对应的生命周期状态 | 关联业务操作及核心按钮 |
| :--- | :--- | :--- | :--- | :--- |
| **C端-客户** | 账号注册页 | 表单页 | `[初始]` | 填写基础表单、**[提交注册]** |
| **B端-管理员** | 申请单列表页 | 列表页 | `全部` | 筛选：状态/提交时间/客户名称、**[新建]** |
| **B端-管理员**| 申请单审核详情页 | 详情页 | `待审核` / `审核中` | 查看企业信息、**[审核通过]**、**[审核驳回(弹窗录入原因)]** |
| ... | ... | ... | ... | ... |
```

---

## 4. 执行约束
1. **绝不遗漏**：只要在《决策表》中定义了人工操作的行，在输出的表格中就必须有承载该操作的页面与按钮。
2. **绝不冗余**：不要为系统级静默行为凭空捏造无关的监控页面，除非说明书中明确提及需要"人工干预看板"。
3. **输出闭环**：推导完成后，必须严格按照 `第5.4节（执行顺序）` 完成文件写入与用户通知，收尾后主动向用户询问：
   > 「✅ 清单已生成并保存。是否需要结合具体的实体属性字段，进一步为您细化某个特定页面（如审核详情页）的原型字段排布与前端校验规则？」

## 5. 文件持久化规范

> 所有推导结果必须同时保存为文件，确保后续技能（如 `page-to-prompt-generate`）可自动读取，实现工作流闭环。

### 5.1 输出路径

所有生成的 UI 页面清单文件，统一保存至项目工程的以下目录：

```
docs/page-list/
```

若该目录不存在，执行时必须自动创建。

### 5.2 文件命名规范

| 情形 | 文件命名规则 | 示例 |
| :--- | :--- | :--- |
| 处理**单个**说明书 | `{实体名称}_UI页面清单.md` | `注册申请单_UI页面清单.md` |
| **批量**处理多个说明书 | 每个说明书各自生成独立文件，命名规则同上 | `合同_UI页面清单.md`、`发货单_UI页面清单.md` |

- `{实体名称}` 取自逻辑资产说明书的文件名前缀（去除 `_逻辑资产说明书` 后缀）。
- 文件名中禁止包含空格，多个词语之间使用下划线 `_` 连接。

### 5.3 文件内容结构

持久化的文件内容必须包含以下固定结构：

```markdown
# {实体名称} UI 页面清单

> **来源说明书**：`docs/logic-asset/{实体名称}_逻辑资产说明书.md`
> **生成时间**：{执行时的当前日期}
> **生成方式**：由 `page-list-generate` 技能自动推导生成

---

{此处粘贴第3章输出的完整 Markdown 表格内容}
```

### 5.4 执行顺序

在推导完成后，必须严格按以下顺序执行：

1. **先写入文件**：使用文件写入工具，将内容保存至 `docs/page-list/` 目录。
2. **再向用户展示**：在聊天区输出与文件一致的内容，供用户即时查阅。
3. **最后告知路径并收尾**：明确告知用户文件已保存的完整相对路径，并执行第4章第3条的"输出闭环"提问。

   示例通知：`✅ 已保存至 docs/page-list/注册申请单_UI页面清单.md`
